# Data Flow & Logic Layers Documentation

---

## 🔹 Layer 1: Edge Level (Ingestion & Smoothing)

When raw data streams arrive at a high frequency from physical IoT sensors or simulated scientific logs, the `edge_dsp.py` module handles the initial filtering and preprocessing.

*   **Buffering:** Data points are temporarily collected within a small, adjustable time window (e.g., 1 to 5 seconds) before being processed or written.
*   **Smoothing Algorithms (DSP):**
    *   **Moving Average:** Applied to eliminate high-frequency random noise and minor fluctuations in steady-state measurements.
    *   **Root Mean Square (RMS):** Utilized for alternating or oscillating signals (e.g., structural vibrations, AC current, acoustic waves) where the total energy amplitude matters more than a simple arithmetic mean.
*   **Storage Strategy (CSV over JSON):**
    *   **Why CSV:** To protect the Edge device’s flash memory or SD card from premature wear and to maximize I/O speed. Data is incrementally appended directly to daily `.csv` files. Reading, parsing, and writing massive JSON arrays for every single sensor tick introduces critical memory overhead, whereas CSV allows ultra-fast, lightweight `append` operations.
    *   **Where JSON Fits:** Static device configurations, calibration constants, and hardware deployment profiles (`metadata.json`) remain unchanged and are safely kept inside each sensor's specific subdirectory.

## 🔹 Layer 2: Analytics Level (`tsfresh` Feature Extraction)

The `feature_extractor.py` module automates mathematical evaluation locally on the edge node, translating raw data streams into statistical features.

1. **Data Ingestion:** The module reads specific chunks of historical CSV data matching a selected experimental timeframe.
2. **Feature Extraction:** It executes `tsfresh.extract_features` to automatically compute hundreds of complex time-series traits:
    *   *Trends:* Detects linear, log, or exponential slopes over time.
    *   *Variability Indexes:* Computes sample entropy, variance, standard deviation, and data spread.
    *   *Frequency Domain Attributes:* Calculates Fast Fourier Transform (FFT) coefficients to find signal periodicities.
3. **Feature Selection:** It runs a basic filter pass to discard irrelevant or constant values, packing the core mathematical signature of the experiment into a highly compact statistical summary.

## 🔹 Layer 3: AI Intelligence Level (Local LLM via Ollama)

The `llm_analyzer.py` module bridges the gap between raw mathematical metrics and human-readable scientific insights without using the cloud.

*   **Data Serialization:** It packages the filtered statistical features generated by `tsfresh` together with the sensor's static engineering metadata into a single, compact JSON payload.
    
    > 💡 **Architectural Insight:** Local LLMs (running via Ollama, such as `qwen2.5-coder:7b` or `deepseek-r1`) cannot process thousands of lines of raw, sequential time-series coordinates. Attempting this causes models to quickly run out of context tokens, slow down, or introduce severe numerical hallucinations. Feeding the model a pre-computed statistical profile ensures fast inference and optimal reasoning performance.

*   **Inference Pipeline:** The LLM processes the structured JSON profile using a tailored system prompt. It returns formal JSON or clean Markdown reports highlighting underlying scientific trends, potential anomalies, and targeted experimental advice.

---

## 🔹 Layer 4: Visualization Level (Dynamic Dashboard)

The frontend web application, located in `dashboard/app.py`, aggregates all backend outputs into a unified user interface.

*   **Real-time Plotting:** Renders fast, interactive time-series plots using lightweight libraries (such as Plotly) directly from the local CSV storage.
*   **Statistical Breakdown:** Displays the exact mathematical metrics extracted by `tsfresh` for precise engineering validation.
*   **AI Insights Delivery:** Outputs the local AI-generated qualitative summaries, anomaly alerts, and automated research interpretations clearly on the screen for the end-user.
